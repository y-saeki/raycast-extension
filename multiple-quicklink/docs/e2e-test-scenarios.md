# E2Eテストシナリオ

`Search Multiple Quicklinks` / `Open Multiple Quicklink` を実機のRaycastにインストールした状態で、手動で確認するためのシナリオ一覧です。ユニットテストは `open()` をスタブに差し替えているため、実際にアプリが開くかどうか・開く順序が保たれるかどうかはここで確認します。

キー表記はmacOSのものです。Windowsでは `⌘` を `Ctrl` に読み替えてください。

## 必須: 順序が保たれるか

複数起動の価値は「並べた順に開く」ことなので、ここが崩れると拡張の意味がなくなります。

- [ ] 起動の速いアプリ(テキストエディタ等)と遅いアプリ(ブラウザの新規プロファイル等)を混ぜたセットを作り、**書いた順に手前へ重なる**ことを確認する
- [ ] 20件(上限)のセットを作り、最後まで開き切ること・全体が数秒で終わることを確認する

順序が崩れる場合は `src/lib/openTargets.ts` の `OPEN_INTERVAL_MS` を見直します。

## 必須: deeplinkの確認ダイアログ

Raycastのドキュメントには、deeplink経由でコマンドを実行する際に確認を求めると記載があります。実際に毎回出るのか、初回だけなのか、Quicklink経由でも出るのかを実測し、結果を `README.md` の該当箇所に反映してください。

- [ ] `Copy Deeplink` でコピーしたURLをブラウザのアドレスバーから実行 → 確認ダイアログの有無を記録する
- [ ] `Create Quicklink for This Set` で作ったQuicklinkをルート検索から実行 → 確認ダイアログの有無を記録する
- [ ] 同じQuicklinkを2回目に実行 → 初回と挙動が変わるかを記録する

## Windows実機

Windowsで確認したものだけをWindows対応として公開する方針のため、公開前に必ず通します。

- [ ] `C:\Users\<name>\...` 形式のパスを含むセットが動く
- [ ] アクションパネルのショートカットが `Ctrl` 系で表示される
- [ ] アプリ指定(実行ファイル名またはパス)が効く
- [ ] `Create Quicklink for This Set` がWindowsでも同じように動く
